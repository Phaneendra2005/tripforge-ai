# TripForge AI

Turn a travel idea into an itinerary you can actually edit.

## Features

- Free-form travel planning
- Structured AI JSON
- Zod validation
- Interactive itinerary
- Edit/remove/add/reorder
- AI stop regeneration
- Dynamic budget calculation
- Loading/error/empty states
- Stale-response protection
- Responsive UI

## Architecture

→ Validation

→ Interactive UI

## Setup

1. Install dependencies:
```bash
npm install
```

2. Create a `.env` file in the root directory:
```bash
GEMINI_API_KEY=your_gemini_api_key_here
```

3. Start the application (starts both frontend and backend):
```bash
npm start
```
The frontend will run on `http://localhost:5173` and the backend will run on `http://localhost:3001`.

## Environment Variables

- `GEMINI_API_KEY`: Required. Your Google Gemini API key.
- `VITE_API_BASE_URL`: Optional. URL for the Express API (defaults to `http://localhost:3001/api`).

## Deployment

**Backend (e.g. Render, Heroku):**
1. Set the Node environment to production.
2. Set `GEMINI_API_KEY` in your hosting provider's environment variables.
3. Configure `cors()` in `server/index.ts` to only accept requests from your production frontend URL.
4. Run `tsx server/index.ts` or compile it with `tsc` and run `node dist/index.js`.

**Frontend (e.g. Vercel, Netlify):**
1. Set `VITE_API_BASE_URL` to your deployed backend URL (e.g., `https://my-backend.com/api`).
2. Do **NOT** expose `GEMINI_API_KEY` to the frontend.
3. Run `npm run build` and deploy the `dist` folder.

## How It Works

TripForge AI prevents hallucinations from breaking the UI by forcing the AI to generate structured data. The React frontend sends a user prompt to the Express backend. The backend constructs a highly detailed schema and calls the Gemini API to enforce JSON output. The backend parses this output and completely validates it using Zod schemas before it ever reaches React. 

## Failure Handling

The application provides graceful failure handling for:
- **Malformed JSON / Wrong Schema**: If the LLM generates invalid data, the backend catches the validation error and sends a controlled error code (`INVALID_SCHEMA`) to the UI instead of crashing React.
- **Empty Responses / API Failures**: Displays a user-friendly error state with a "Try Again" action.
- **Timeout**: The frontend utilizes standard timeouts and abort signals to prevent infinite loading.
- **Stale Responses**: Implemented via a strict `AbortController` and `requestRef` tracking to guarantee that an older, delayed AI response cannot overwrite a newer generated result.

## Interview Talking Points

### Why structured JSON?
Because raw LLM text is unpredictable, un-parseable, and difficult to render reliably as distinct editable components. Structuring forces the AI into a predictable shape.

### Why Zod?
To validate runtime data because TypeScript types disappear at runtime. We cannot inherently trust data generated by an LLM to fulfill the TS interfaces automatically.

### Why backend proxy?
To keep the Gemini API key out of the browser. Placing an API key in a client-side bundle exposes it to malicious actors.

### How do you prevent stale responses?
Request IDs / `AbortController` ensure an older request cannot overwrite a newer result. If the user clicks "Generate" twice, only the final request is allowed to update the React state.

### What happens if AI returns malformed JSON?
Parsing fails and the application enters a controlled error state instead of attempting to render invalid or partial data, which would crash the UI.

### What happens if the schema is wrong?
Zod rejects the result before it reaches React state, ensuring the UI always receives exactly what it expects.

### Why calculate budget on the frontend?
The itinerary is editable, so derived values must reflect the current application state rather than stale AI output. Editing a stop immediately recalculates the total cost deterministically.
